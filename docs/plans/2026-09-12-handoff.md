# whispr — engineering handoff

Local voice dictation for Linux. Hold a key, speak, release; the text is typed
into whatever window has focus. No network, no API key.

This document is the entry point: architecture, configuration, the constraints
that are not discoverable from the code, what is and isn't verified, and where
to start. Read it before changing anything in `src/`.

---

## 1. Current state

Working and in daily use.

| | |
|---|---|
| Engine | Whisper `base.en` via `libwhisper`, Vulkan on an RTX 5070 Ti |
| Latency | ~0.5s key release → text (210 ms transcribe + 280 ms typing) |
| Encode | 7.5 ms on Vulkan (278 ms on CPU) |
| Accuracy | WER 0.00 / 0.095 / 0.158 on the `short` / `plain` / `jargon` fixtures |
| Upstream | `ggml-org/whisper.cpp` pinned at **v1.9.4** (submodule) |
| Size | ~3200 lines: C daemon (6 modules), 4 shell helpers, tests, diagnostics |

### Keys (Keychron V6, the four symbol keys above the numpad)

| Key | Keysym | Action |
|---|---|---|
| circle | `XF86Tools` | hold = push-to-talk; release transcribes and types |
| square | `XF86Launch6` | tap = hands-free; stops ~2s after you stop talking |
| triangle | `XF86Launch5` | tap = toggle on/off manually |
| X | `XF86Launch7` | tap = cancel, discard without typing |

### Commands

```sh
whispr start | stop            # push-to-talk, bound to key press and release
whispr dictate                 # hands-free, ends on silence
whispr toggle | cancel
whispr status [--json]         # idle | recording | transcribing
whispr reload                  # re-read config, including an engine swap
whispr daemon [--no-inject] [-v] [-c PATH]
```

`--no-inject` prints transcripts to stdout instead of typing them. Use it for
anything automated — it is the difference between a test and a test that types
into your editor.

## 2. Architecture

```
  WM keybind ──► whispr (client) ──unix socket──► whispr daemon
                                                     │
                               pw-record ────────────┤ f32 16kHz mono
                                                     │
                               libwhisper ───────────┤ worker thread
                                                     │
                               whispr-inject ◄───────┘ ydotool → focused window
```

One binary is both daemon and client. The daemon runs an `epoll` loop over the
listen socket, the capture pipe, and three timerfds (recording watchdog, idle
unload, worker-done eventfd). Transcription and injection run on a single worker
thread so `status` never stalls behind a 300 ms `ydotool type`.

### Four decisions that shaped everything

**The daemon does not grab keys — the WM does.** Only 1 of 26
`/dev/input/event*` nodes is readable by an ordinary user here, and joining the
`input` group would let any process on the machine keylog the session. So the WM
owns the hotkey and invokes a tiny client over a Unix socket. This is also what
makes the daemon portable: it never learns which compositor it runs under. The
cost is that push-to-talk needs a WM that can bind key *releases* — Hyprland,
sway and sxhkd can; KDE and GNOME cannot and must use toggle or hands-free.

**Hotkeys must be modifier-free.** With a modified key you release the combo and
the daemon begins typing while the modifier is still physically down, turning
every character into a window-manager shortcut. The symbol keys carry no
modifier, which is the entire reason they were chosen.

**C linking `libwhisper`, not a language binding.** It `#include`s `whisper.h`
directly, so struct layouts cannot drift the way a ctypes mirror of
`whisper_full_params` would. This is the low-risk option, not the ambitious one.

**The model loads when recording *starts*, not when it ends.** Loading overlaps
with speech, so the wait after key release is decode time only. It is dropped
after 10 minutes idle (measured: 317 MiB → 7 MiB VRAM).

## 3. Configuration

`~/.config/whispr/config`, flat `key = value`. Unknown keys are *reported*, not
ignored, so a typo is visible. `whispr reload` applies changes without a restart;
a reload during transcription is deferred until the worker is idle.

| Key | Default | Notes |
|---|---|---|
| `engine` | `whisper` | or `parakeet` |
| `whisper.model` | `…/ggml-base.en.bin` | |
| `whisper.initial_prompt` | *(empty)* | **biggest accuracy lever — see §5** |
| `whisper.vad` | `true` | Silero; leave on |
| `use_gpu` / `gpu_device` | `true` / `0` | `false` falls back to CPU, no rebuild |
| `n_threads` | `8` | |
| `source` | *(empty)* | empty = default input device |
| `max_record_seconds` | `120` | watchdog; a lost key-release cannot hang it |
| `min_record_ms` | `300` | shorter is a brushed key, dropped silently |
| `skip_start_ms` | `300` | discards the start cue from the capture — §4 |
| `silence_stop_ms` | `2000` | hands-free: quiet this long ends it |
| `voice_dbfs` | `-28.0` | above this counts as speech — §5 |
| `dictate_wait_s` | `10` | hands-free gives up if nothing is ever said |
| `min_rms_dbfs` | `-50.0` | quieter than this never reaches the model |
| `idle_unload_seconds` | `600` | |
| `append_space` | `true` | |

Typing speed lives in `whispr-inject`: `WHISPR_TYPE_DELAY_MS` (2) and
`WHISPR_TYPE_HOLD_MS` (1).

## 4. Constraints that will bite you

None of these are visible from the code. Most cost hours to find.

**`~/.local/bin` is not on `PATH`** — not for Hyprland (which runs with the
login-session PATH) and not for the systemd user manager. A bare `whispr` in a
keybind is not found, and the daemon's `execvp` of `whispr-inject` /
`whispr-notify` fails and `_exit(127)`s. Symptoms are *total silence* — no
typing, no sound, no notification — while the hotkey, capture and transcription
are all working. Binds use absolute paths; the daemon falls back to its own
directory and now logs failed execs. **If something mysteriously does nothing,
check PATH first.**

**xkb renames F13–F16** to `XF86Tools` and `XF86Launch5-7`. Binding `"F13"`
silently never matches. The keycode form (`code:191`) is no good either — this
Hyprland Lua DSL stores it verbatim with `keycode: 0` and never matches.
**Keysym names are what work.** Use `scripts/probe-keys.sh` on any new key.

**The microphone hears the room.** Any audible speech — a video on another
machine, a call on speaker — is transcribed faithfully into your text. This is
inherent to the design. It also makes "the model hallucinated" a claim to
distrust: verify a genuinely silent room before believing it.

**Whisper does confabulate from genuinely low-information audio**, and this tool
types the result into a focused window. Four guards, weakest first: an RMS gate,
`suppress_nst`, `no_speech_thold`, and Silero VAD. VAD is the one that reliably
works; the cheap checks run first and cost nothing.

**The start cue is played while the mic is already open**, so the capture would
otherwise contain whispr's own beep. `bell.oga` is 139 ms and `skip_start_ms` is
300 ms. If you change the cue, check its duration — `message.oga` is 311 ms and
did not fit inside a 250 ms window.

**Every exit from `RECORDING` must emit a terminal notification**, or the
"Recording" toast outlives the recording. Paths: normal stop, cancel, too-quiet,
too-short (`dismiss`), watchdog timeout. Add a path, add an event.

**ydotool defaults to 40 ms/char** — 3.8s for one sentence, against 210 ms of
transcription. Typing was 95% of visible latency. Now 2/1 (0.28s/sentence);
measured, 1/1 works and 0/0 drops half the characters, so 2/1 is fast *with
margin*. A slower client has less headroom than a terminal.

**PipeWire monitor sources suspend when idle** and resume late, which makes
sink-monitor loopback testing intermittently capture nothing. The real capture
path does not suffer this. Do not trust a single loopback result.

## 5. Accuracy

`whisper.initial_prompt` is the cheapest and largest lever available. It ships
**empty**: priming only helps for words the speaker actually says, so a shipped
vocabulary would bias every other user's decoder toward terms they never use.
The numbers below use the fixtures' own vocabulary, which is what a user filling
this in for their jargon would get:

| | jargon WER |
|---|---|
| no prompt | 0.421 — *"Hyperland on cacheOS with Pipewire YDO tool … Vulcan back end"* |
| with prompt | 0.158 — *"Hyperland on CachyOS with PipeWire ydotool … Vulkan backend"* |

Add terms as you hit ones it mangles. "Hyprland" still comes out "Hyperland" and
is worth adding. Escalation path after the prompt: `ggml-small.en.bin`, then
reconsider Parakeet.

### Parakeet is implemented but is not the default

| | short | plain | jargon | wall clock | size |
|---|---|---|---|---|---|
| whisper base.en + prompt | 0.000 | 0.095 | **0.158** | **221 ms** | **142 MB** |
| parakeet tdt-0.6b-v3 | 0.000 | 0.143 | 0.474 | 434 ms | 1.2 GB |

Most of the jargon gap is structural: Parakeet TDT has no prompt conditioning to
offer. Against an *unprimed* Whisper the two are close (0.421 vs 0.474), so this
is a statement about the workload — short English dictation dense with proper
nouns — not about the model, which is strong on general speech. Switch with
`engine = parakeet` + `whispr reload`. Worth revisiting for non-English: v3
covers 25 languages, `base.en` is English-only.

### Vulkan

Correct on both engines — WER identical to CPU on every fixture. Parakeet's
first run spends ~3.9s compiling SPIR-V shaders; warm, Vulkan beats CPU on both.
Do not benchmark a cold Vulkan run.

### Audio levels here

Room floor -31.6 dB, speaker -20.7 to -14.3 dB, hence `voice_dbfs = -28`. These
thresholds are tuned to one room, one mic and one voice.

## 6. Testing

```sh
./tests/run-tests.sh          # WER against recorded fixtures — fast, automated
./scripts/acceptance.sh       # operator-driven, drives the real hotkeys
./tests/record-fixtures.sh    # re-record fixtures
```

`run-tests.sh` asserts **word error rate under a threshold**, not string
equality — ASR never matches byte-for-byte. `wer.py` normalizes first, so
`"sixty four"` and `"64"` compare equal and contraction style never counts.
Thresholds are a **ratchet: tighten only.** A threshold loosened to make a
failing run green catches nothing ever again.

One fixture is silence. Whisper emits `[BLANK_AUDIO]`, `[Music]` or subtitle
credits over room tone, and in this tool that text would be typed into whatever
you had focused — so marker-stripping is tested, not assumed.

### Diagnostics

| | |
|---|---|
| `scripts/probe-keys.sh` | what does this physical key actually send? |
| `scripts/diag-key.sh` | a bound key isn't firing — is it the bind or the exec? |
| `scripts/acceptance.sh` | full operator-driven pass, results saved to `/tmp` |
| `whispr-doctor` | PATH, capture, ydotoold, uinput, models, config, daemon — at once |

`diag-key.sh` exploits the fact that Hyprland *consumes* a key it has a bind for:
`wev` seeing the key means the bind isn't matching; `wev` silent with no state
change means the bind matched and the exec failed.

## 7. Verified vs not

**Verified** end to end with a real voice through the real hotkeys
(`acceptance.sh`, 5/5): silence produces nothing; push-to-talk; first word not
clipped when speaking immediately; toggle; cancel discards. Also: injection into
a real window, idle unload (317→7 MiB), the recording watchdog, reload during
transcription under TSan, orphan cleanup on SIGKILL, and clean ASan / UBSan /
TSan runs.

**Not verified:**

- Any other voice, microphone, or room. Silence thresholds are tuned to one
  measured -31.6 dB floor.
- Typing speed outside a terminal. 2/1 is measured in a terminal only; back off
  to 4/2 (WHISPR_TYPE_DELAY_MS / WHISPR_TYPE_HOLD_MS) if characters go missing
  in a slower client.
- Behavior after a reboot. Units are enabled and `modules-load.d` handles
  `uinput`, but nothing has actually rebooted.
- Any WM other than Hyprland. The snippets in `wm/README.md` are written from
  documentation, not run.
- Parakeet beyond three fixtures. A 0.05 WER difference over a 21-word utterance
  is one word.

## 8. Open questions

- Is 2/1 typing safe in the slowest target app, or should the default be 4/2?
- Should hands-free be the default mode rather than push-to-talk?
- Is `silence_stop_ms = 2000` right? 5s was originally requested; 2s was a
  recommendation that has not been lived with yet.
- Does the engine vtable still earn its keep now that Parakeet lost, or is it
  speculative generality that should collapse back to Whisper?
- Should fixtures cover a second speaker or a noisy room before the thresholds
  are trusted anywhere but this machine?
