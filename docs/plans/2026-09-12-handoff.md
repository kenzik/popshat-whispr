# whispr — handoff, 2026-09-12

Built in one session from the plan in `2026-09-12-voice-dictation-service.md`.
All phases complete and in daily-use condition. This document is written to be
argued with: the decisions, the measurements behind them, the bugs and their
root causes, and an explicit list of what is *not* verified.

## What it is

Hold a key, speak, release — the text is typed into whatever window has focus.
Local, no network. ~0.5s from key release to text.

```
  WM keybind ──► whispr (client) ──unix socket──► whispr daemon
                                                     │
                               pw-record ────────────┤ f32 16kHz mono
                                                     │
                               libwhisper ───────────┤ worker thread
                                                     │
                               whispr-inject ◄───────┘ ydotool → focused window
```

~3200 lines: a C daemon (`src/`, 6 modules), three POSIX shell helpers, a WER
test harness, and three diagnostic scripts written while debugging.

## Decisions worth challenging

**The daemon does not grab keys; the WM does.** Only 1 of 26
`/dev/input/event*` nodes is readable by this user, and joining `input` would
let any process keylog the session. So the WM owns the hotkey and calls a tiny
client over a Unix socket. This is also what makes it portable — the daemon
never learns which compositor it runs under. Cost: push-to-talk needs a WM that
can bind key *releases*. Hyprland, sway and sxhkd can; KDE and GNOME cannot, and
must use toggle or hands-free.

**Modifier-free hotkeys, non-negotiable.** With a modified key you release the
combo and the daemon types while the modifier is still physically down, turning
every character into a WM shortcut. The four symbol keys above the numpad are
modifier-free and already send F13–F16 in firmware.

**C linking libwhisper, not a binding.** It `#include`s `whisper.h`, so struct
layouts cannot drift the way a Python/ctypes mirror of `whisper_full_params`
would. This is the low-risk choice, not the ambitious one.

**The model loads when recording *starts*.** Loading overlaps with speech, so
the wait after key release is decode time only. Dropped after 10 min idle
(verified: 317 MiB → 7 MiB VRAM).

**Whisper stays the default over Parakeet** — see below.

## Measurements

### Accuracy (recorded fixtures, this speaker, this mic)

| | short | plain | jargon | wall clock | size |
|---|---|---|---|---|---|
| whisper base.en + prompt | 0.000 | 0.095 | **0.158** | **221 ms** | **142 MB** |
| whisper base.en, no prompt | 0.000 | 0.095 | 0.421 | 221 ms | 142 MB |
| parakeet tdt-0.6b-v3 | 0.000 | 0.143 | 0.474 | 434 ms | 1.2 GB |

`whisper.initial_prompt` is the single biggest accuracy lever: jargon 0.421 →
0.158, fixing cacheOS→CachyOS, "YDO tool"→ydotool, "Vulcan back end"→Vulkan
backend. Parakeet TDT has no prompt conditioning, which is most of the gap —
unprimed, the two are close (0.421 vs 0.474).

**The plan predicted Parakeet would win on both accuracy and speed. It did not.**
On this workload — short English dictation dense with proper nouns — it loses on
both. That is a finding about the workload, not about Parakeet, which is SOTA on
general speech. It is implemented, working, and one config line away
(`engine = parakeet` + `whispr reload`). Worth revisiting for non-English (v3
covers 25 languages; `base.en` is English-only).

### Vulkan

Correct on both engines: WER identical to CPU on every fixture. Parakeet's first
run costs ~3.9s compiling SPIR-V shaders, which I initially misread as the
backend being 8× slower than CPU. Warm, Vulkan wins on both engines. **The plan's
main open risk — whether ggml's Vulkan backend handles FastConformer's depthwise
convolutions — is resolved in Vulkan's favour.**

### Audio levels (drive the silence thresholds)

Room floor -31.6 dB; this speaker -20.7 to -14.3 dB. `voice_dbfs = -28` sits in
that gap. Both thresholds are config knobs documented with which way to move them.

## Bugs found, and why they were hard

Listed because the root causes are more instructive than the fixes, and because
several were mine rather than the code's.

1. **`~/.local/bin` is not on `PATH`** — twice. Hyprland runs with the
   login-session PATH, so a bare `whispr` in a bind was never found; the systemd
   user manager likewise, so the daemon's `execvp` of `whispr-inject` and
   `whispr-notify` failed and `_exit(127)`'d **silently**. Every visible symptom
   pointed at the hotkey or the model. Fixed by absolute paths, an exe-relative
   fallback, and — the important part — *reporting* failed execs.

2. **Blocking capture pipe deadlocked the event loop.** `audio_drain`'s `EAGAIN`
   exit could never fire, so the loop sat in `read()` and stopped serving the
   socket. Read end is now non-blocking; `audio_stop` restores blocking for the
   final drain, where EOF is the correct terminator.

3. **`reload` could free the model under the worker thread.** The engine reads
   config through a pointer for a whole transcription and `engine_unload()` frees
   the context the worker may be inside. Found by *reading*, not testing: TSan had
   passed the path, because reloading an identical config leaves `engine_changed`
   false and the dangerous branch never runs. It only fires when the model
   actually changes — the exact reason the command exists.

4. **Orphaned recorders.** A SIGKILLed daemon left `pw-record` running forever
   with the mic open. `PR_SET_PDEATHSIG` makes the kernel handle it, covering
   crashes as well as kills.

5. **xkb renames F13–F16** to `XF86Tools`/`XF86Launch5-7`, so `bind("F13", …)`
   silently never matches. The `code:191` form is also useless here: this Lua DSL
   stores it verbatim with `keycode: 0`. Keysym names are what work.

6. **Whisper confabulates from low-information audio**, and this tool types the
   result. Guarded by Silero VAD (`silence.wav` → empty), plus an RMS gate,
   `suppress_nst` and `no_speech_thold`. **Caveat:** I attributed several
   alarming transcripts to hallucination when they were almost certainly a video
   playing in the room being transcribed *correctly*. The guards are sound, but
   that diagnosis outran its evidence. A verified-silent baseline should have
   been established first.

7. **Every exit from `RECORDING` must clear the "Recording" toast.** The
   too-short-tap path was the one that did not, leaving a recording indicator up
   for 20s with nothing recording.

8. **Typing was 95% of visible latency.** ydotool defaults to 40 ms/char — 3.8s
   for one sentence against 210 ms of transcription. Now 2/1 (0.28s); 0/0 drops
   half the characters, so this is fast *with margin*, not as fast as possible.

Also three of my own harness bugs worth not repeating: backgrounding a shell
*function* so `$!` was the subshell and `kill` orphaned the recorder (this
produced 200-second "fixtures"); `wev` emitting nothing until its window has
focus, which is indistinguishable from a key that sends nothing; and merging the
daemon's stdout with whisper.cpp's stderr, then filtering them apart with a grep
that silently gave up when the Vulkan backend wrote control bytes.

## Verified vs not

Verified end to end, with this speaker's voice through the real hotkeys
(`scripts/acceptance.sh`, 5/5): silence produces nothing; push-to-talk; **first
word not clipped** when speaking immediately; toggle; cancel discards. Plus
injection into a real window, idle unload, the watchdog, reload-during-
transcription under TSan, and clean ASan/UBSan/TSan runs.

**Not verified:**

- Any voice but this one, any mic but the TONOR G11, any room but this one. The
  silence thresholds are tuned to a measured -31.6 dB floor.
- Injection into Electron/browser targets at 2/1 typing speed. Tested in a
  terminal; a slower client has less headroom and may drop characters.
- Behaviour after a reboot. Units are enabled and `modules-load.d` handles
  `uinput`, but nothing has actually rebooted.
- Any WM other than Hyprland. Snippets in `wm/README.md` are written from the
  docs, not run.
- Parakeet beyond the three fixtures. Three short clips is a small sample, and a
  0.05 WER difference over 21 words is one word.

## Known limitations

- **The mic hears the room.** A video playing nearby ends up in your text. This
  is inherent, not a missing feature, and it cost a long detour in this session.
- `base.en` still writes "Hyperland". Add terms to `whisper.initial_prompt`;
  that is the cheapest lever. Next steps after that are `small.en`, then
  revisiting Parakeet.
- The PrtSc key sends main-row `4` (a pre-existing firmware issue, documented in
  the user's `binds.lua`). Unrelated to whispr, fixable only in VIA.
- CMake 4.4.3 lives in `vendor/toolchain/` — deliberately *not* `~/.local/bin`,
  so it cannot shadow a pacman `cmake` installed later.

## Questions worth pressing on

- Is 2/1 typing safe in *your* slowest app, or should it back off to 4/2?
- Should hands-free be the default mode rather than push-to-talk?
- Is `silence_stop_ms = 2000` right? The original request was 5s; 2s was my
  recommendation and it has not been lived with yet.
- Does the engine vtable earn its keep now that Parakeet lost, or is it
  speculative generality that should be collapsed back to Whisper?
- Should the fixtures cover a second speaker or a noisy room before the
  thresholds are trusted anywhere but here?
